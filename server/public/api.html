TLI Companion API

Version 1 · free · no key needed

Auction House prices seen in game by TLI Companion players, and builds shared from the planner (see Shared builds), for your site, bot or tool. Read only, open to every website (CORS), cached 10 minutes.

  • Our prices only: Auction House searches captured by TLI Companion players. Prices from other sources are not included.
  • At least 3 players: an item is listed only if at least 3 players saw its price in the last 7 days. A history day is listed only if 3 players saw it that day.
  • Prices in FE (Flame Elementium). Item ids are the game's ids.
  • Version 1 stays stable: fields can be added, never removed or renamed.

One item, with its history

GET https://tlicompanion.com/api/public/v1/prices/100200?days=30

Same fields as above, plus days (1 to 120, 30 by default) and history: one entry per day (UTC).

"history": [
  { "day": "2026-10-26", "median": 0.0121, "low": 0.0110, "high": 0.0140, "players": 21 },
  { "day": "2026-10-27", "median": 0.0125, "low": 0.0118, "high": 0.0131, "players": 17 }
]

Fields

FieldMeaning
priceCurrent price: median of the latest price each player saw in the last 7 days.
players7dNumber of players who saw a price for this item in the last 7 days.
updatedAtWhen the latest price for this item was seen.
change24h, change7dChange compared with the daily median 1 day and 7 days ago. 0.05 = +5 %. null when unknown.
categorySame categories as the Prices page, other when unknown.
iconItem icon URL, or null.

Limits

  • 60 requests per minute per address. Above that, the answer is 429.
  • Data changes at most every 10 minutes: no need to ask more often. Fetch the full list once and keep it.
  • Errors come as { "error": "…" } with a 4xx code. An unknown item, or one seen by fewer than 3 players, gives 404.

Example

const r = await fetch('https://tlicompanion.com/api/public/v1/prices');
const { items } = await r.json();
const byId = Object.fromEntries(items.map((i) => [i.id, i]));
console.log(byId[100200]?.price);

  • Text as in the game: names and every affix line are the English game texts, one string per line.
  • Talent nodes: x = column from the left, y = row from the top, both starting at 0, as the tree is shown in game.
  • gear[].other: lines without their own slot in the planner (corrupted lines, enchantments…).
  • extraEffects: effects read from the game with no place in the planner (divinity slate effects…), or added by hand.
  • stats: computed by the planner (no damage), to check an import. null if the build could not be computed.
  • Only what players choose to share, and nothing from their account. An author can remove a share: the API then gives 404.
  • Same rules as the price API: CORS open, version 1 stable (fields only added), 60 requests per minute.

Game IDs (gameIds)

When a build was imported from the game log, each part also carries the game's own IDs (the gameIds fields in the example above), so you can match it against your data by number instead of comparing texts. An ID is only given for parts that are unchanged since the import: if the player edits an item or a skill by hand, that part gets gameIds: null. Builds made by hand have null everywhere and build.game: null.

  • modId: the game's modifier ID of an affix, with its rolled values as the game sends them, and the text lines it gives. field says which list the lines are in (baseStats, prefixes, suffixes, legendaryAffixes, other…). An affix unknown to tlidb still has its modId, with empty lines.
  • itemId: the game's base ID of the item, skill or memory. legendaryId: the legendary's own ID.
  • Talents: gameId on each allocated node (null on reflected nodes), careerId of the tree. Pacts: servantId, and for each destiny its item ID, the board point (pointId, “XYY” = pact X, point YY) and its modifier.
  • game.slates: talent IDs given by each divinity slate.

API de TLI Companion

Version 1 · gratuite · sans clé

Les prix de l'hôtel des ventes vus en jeu par les joueurs de TLI Companion, et les builds partagés depuis le planner (voir Builds partagés), pour ton site, ton bot ou ton outil. Lecture seule, ouverte à tous les sites (CORS), mise à jour toutes les 10 minutes.

  • Nos prix seulement : les recherches à l'hôtel des ventes captées par les joueurs de TLI Companion. Les prix d'autres sources ne sont pas inclus.
  • Au moins 3 joueurs : un objet n'apparaît que si au moins 3 joueurs ont vu son prix ces 7 derniers jours. Un jour de l'historique n'apparaît que si 3 joueurs l'ont vu ce jour-là.
  • Prix en FE (Flame Elementium). Les identifiants des objets sont ceux du jeu.
  • La version 1 reste stable : des champs peuvent être ajoutés, jamais retirés ni renommés.

Merci de nous citer

Affiche « Prices: tlicompanion.com » (ou « Prix : tlicompanion.com ») avec un lien vers https://tlicompanion.com là où tu montres ces prix.

Tous les objets

GET https://tlicompanion.com/api/public/v1/prices

Renvoie items : pour chaque objet id, name (en anglais), icon, category, price, players7d, updatedAt, change24h, change7d. Le détail des champs est dans la version anglaise de cette page.

Un objet, avec son historique

GET https://tlicompanion.com/api/public/v1/prices/100200?days=30

Les mêmes champs, plus days (1 à 120, 30 par défaut) et history : un point par jour (UTC) avec median, low, high et players.

Limites

  • 60 requêtes par minute et par adresse. Au-delà, la réponse est 429.
  • Les données changent au plus toutes les 10 minutes : inutile de demander plus souvent.
  • Les erreurs arrivent sous la forme { "error": "…" } avec un code 4xx. Un objet inconnu, ou vu par moins de 3 joueurs, donne 404.

Builds partagés

Les builds partagés depuis le planner de TLI Companion (la plupart importés directement du jeu). Un joueur clique sur Partager et obtient un lien du type https://tlicompanion.com/b/Ab3dEf7h. Le même build en JSON :

GET https://tlicompanion.com/api/public/v1/builds/Ab3dEf7h

Exemples réels (le lien ouvre le build dans le planner, le JSON montre ce que renvoie l'API) :

BuildPlannerAPI

Renvoie build au format tlicompanion-build version 1 : héros et traits, souvenirs, équipement (chaque ligne d'affixe en texte anglais), compétences et soutiens, nœuds de talents (x = colonne, y = ligne, à partir de 0), pactes et leurs anneaux, tablettes de divinité, effets en plus et stats calculées (sans les dégâts). Le détail et un exemple sont dans la version anglaise de cette page. Seuls les builds que les joueurs choisissent de partager sont lisibles, sans rien de leur compte ; un partage retiré par son auteur donne 404.

Identifiants du jeu (gameIds) : un build importé depuis le log du jeu porte aussi les numéros du jeu de chaque élément (objet, légendaire, affixe avec ses valeurs, compétence, soutien, trait, souvenir, nœud de talent, pacte, destinée, tablette). Les autres outils peuvent ainsi retrouver chaque élément par son numéro, sans comparer des textes. Une partie modifiée à la main après l'import a gameIds: null. Le détail est dans la version anglaise de cette page.
